# Super Mario Bros. (World) — desktop

Portable Windows x64 EXE, Linux x86-64 AppImage, and macOS Apple Silicon app. The existing FCEUmm core and World ROM are used; Android files are not changed. This is an NES game: its original 256×240 image is scaled sharply with nearest-neighbor to fit the display, including 4K fullscreen, keeping a 4:3 image and black bars as needed. Upscaling does not create native 4K detail. F11 toggles fullscreen.

Settings: F1 or Escape (also mouse middle button or controller button 9). Click or use arrow keys and Enter to choose a row, then press a key, mouse button, or controller button to bind it. Reset Controls restores all defaults. Bindings and cheats are saved per user. Keyboard arrows/WASD move, Z/Space jumps, X/Ctrl fires, Enter starts, right Shift selects; mouse left jumps, right fires. Gamepad analog axis 0/1 and D-pad automatically control movement; buttons 0/1/2 jump/fire. Axis and D-pad are fixed, not remappable. Hot plugging is supported. No touch overlay.

The in-game update check uses the separate desktop catalog in `updates/desktop/`; if an update is available, press U in Settings to download to Downloads. It validates size and SHA-256 against the catalog and never executes an update automatically. Run the new portable file yourself; on macOS unzip the new app. Catalog and release artifacts must be updated together when publishing future releases; no automatic publication is implied.

Each OS has its own packaging smoke-test script. GitHub Actions runs self-tests against the actual ROM/core and bundled app with simulated keyboard, mouse, and gamepad input and dummy video/audio. This is not physical controller, display, sound, latency, or complete-game testing. Native Windows/macOS builds are unsigned; macOS Gatekeeper may block the app. AppImage compatibility depends on glibc and graphics/audio drivers. Linux smoke test uses AppImage extraction to avoid requiring FUSE.

Runtime dependencies: pygame 2.6.1 wheels (including SDL native components) in `desktop/vendor`; Python and those components are bundled by PyInstaller. Wheel filenames and hashes are checked by CI. The FCEUmm source remains in the existing game tree. Build-time tools (CMake, compiler, Python, PyInstaller and pinned-hash appimagetool) are installed/downloaded by CI, not vendored here. See the licenses inside each wheel and existing emulator sources. Building or redistributing ROMs may require rights.
